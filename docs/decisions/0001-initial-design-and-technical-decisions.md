# 0001 The Last Block: initial design and technical decisions

Date: 2026-11-12
Status: first version complete; numbers and feel are provisional defaults

## Overview
A single-player first-person shooter for the browser. Fictional setting: enemy airborne troops break into Taichung, and the player holds the civic center in the 7th Redevelopment Zone through six waves.

## Design and technical decisions

| # | Decision | Reason | Rejected alternatives |
|---|----------|--------|-----------------------|
| 1 | three.js r160, vendored as a single file in `vendor/`, with no build step | Runs offline with `python3 -m http.server`; r160 is one of the last single-file ES module builds | Vite + npm: an extra toolchain with no benefit at this size. Babylon or PlayCanvas: larger |
| 2 | Single-player, six-wave defense of the command post in the park | One scene gives a complete arc; enemies arrive along four roads, so the whole map gets used | Linear levels: need several maps and scripting |
| 3 | Low-poly models with procedural textures (facades, signs, and the flag are drawn on canvas) and audio synthesized with Web Audio | No external assets means no licensing questions and no downloads | Realistic asset packs: licensing and size costs |
| 4 | The map is a stylized layout. Road names and landmarks (City Hall, the National Taichung Theater, Maple Garden, the park, Taiwan Blvd, Wenxin Rd, Huilai Rd, Henan Rd, Huizhong Rd, Shizheng Rd) are real, but positions, sizes, and building counts are arranged for gameplay | There is no survey data, so the game does not claim accuracy and says so on the menu | Modelling from OpenStreetMap data: possible, left for a later stage |
| 5 | The department store is labelled generically, with no real brand names or logos | Avoids trademark issues | None |
| 6 | Enemies path with a BFS flow field on a 2 m grid, recomputed from the player's position every 0.35 s. A cell is blocked if any obstacle, inflated by the unit radius, touches it | All enemies share one field, so cost does not grow with their number; a path through cell centres never clips an obstacle | A* per enemy; NavMesh (needs extra tooling). A 4 m grid with the same blocking rule seals the sandbag post into an island and enemies fall back to walking straight into walls |
| 7 | Collision and ray casting are hand-written AABB code in `core.js`, with no physics engine | The scene is all axis-aligned boxes, so this is the fastest and the easiest to test | cannon or rapier: far more than needed |
| 8 | Pure logic (`core.js`, `map.js`, `config.js`) does not depend on three.js or the DOM | It can be tested with `node --test` | Everything in `main.js`: untestable |
| 9 | Looking and firing do not depend on Pointer Lock. Without it, cursor movement and edge turning act as a fallback | Some embedded browsers do not support mouse lock, and the game should still be playable there | Requiring the lock |
| 10 | The enemy is described only as a military force, with no real people and no targeting of any ethnic group | The story is a fictional defense against an invading army | None |
| 11 | Kills pay money and an armory (key B) sells weapons. Opening it pauses the fight. It can be opened at any time and from anywhere on the map. It sells the sniper rifle, the Desert Eagle, ammo for both, grenades, and medkits | Gives kills a second purpose and makes the weapons goals to work toward; fun is preferred over a tight economy, so a surplus of money late in a run is accepted | A buy phase only between waves, or a shop tied to the command post: more tension, but the player could not react to running dry mid-wave |
| 12 | The sniper rifle uses a full-screen scope overlay, hides the view model while scoped, and is perfectly accurate only when scoped | Reads clearly as a sniper and keeps it weak from the hip | A magnified picture-in-picture scope: needs a second render pass |
| 13 | The pause screen offers Resume and Main Menu; returning to the menu discards the run | A run is short, so there is nothing worth saving | Confirm dialog before quitting: one more click for little benefit |
| 14 | Modules are versioned through an import map in `index.html`, generated by `scripts/stamp.mjs` from a hash of each file's content. The menu shows the build id | GitHub Pages caches every file for about 10 minutes, so after a release a browser could run old and new modules together; hashing per file also keeps unchanged files cached | A bundler with hashed filenames: adds the build step decision 1 avoided. A single version query on the entry script: nested imports would still be stale. A service worker: far more moving parts |
| 15 | First-person weapons are GLB models (M16, Beretta 92, M24, Desert Eagle), loaded with three.js's GLTFLoader. Each file is normalized in code from a small table (real length, barrel direction, barrel height); the box models remain as placeholders and as the fallback. Weapons were renamed to match the models | The models arrive 1 unit long with inconsistent barrel directions, so fixing them in code avoids re-exporting; a missing or broken file never stops the game | Editing each model in Blender to a common origin and scale: cleaner files, but a manual step for every new model |
| 16 | Untextured models get a flat dark steel material and metalness is forced to 0 on textured ones | The scene has no environment map, so metallic PBR materials would render black | Adding an environment map: more realistic, but changes the look of the whole scene |
| 17 | First-person arms are built from boxes (sleeve, cuff, glove), one rig per weapon, attached to the gun group. Each arm is defined by a hand point and an elbow point | Needs no assets or skeleton, follows recoil, reload, and aiming for free, and is easy to retune per weapon | A rigged arms model with animations: better looking, but needs a model and an animation set per weapon |
| 18 | Enemy soldiers use one rigged GLB (Mixamo skeleton, four clips made in Tripo). Each enemy is a skeleton clone with its own animation mixer; the run clip plays while approaching and the aim clip while fighting, cross-faded; death plays once and holds | One model keeps the download small (1 MB) and the three soldier types are told apart by tint and scale | A separate model per type: more variety, three times the assets and tuning |
| 19 | Horizontal root motion is removed from the clips at load, and playback speed follows the enemy's actual speed | The clips walk the character forward, but positions are driven by the game's pathfinding, so both would fight; matching speed limits foot sliding | Driving movement from root motion: would need the pathfinding rewritten around the animation |
| 20 | The box figure is still built for every soldier and hidden; its parts remain the hit boxes | Hit detection, headshots, and the fallback when the model fails to load all keep working unchanged | Ray casting against the skinned mesh or bone-attached boxes: more exact, more cost and code |
| 21 | The enemy's rifle is the M16 GLB parented to the right-hand bone, with one grip rotation for the run clip and one for the aim clip, blended when the clip changes | The wrist is turned about 90 degrees differently between the two clips, so a single rotation leaves the barrel sideways in one of them | Inverse kinematics for both hands: correct in every pose, far more work |
| 22 | The first-person arms are cut from the soldier model: triangles skinned to the arm, forearm, hand, and finger bones are kept, and the upper-arm and forearm bones are re-parented under the gun group and aimed in code from a palm point and an elbow point per weapon. Fingers are curled by a fixed angle. The box arms remain as the fallback | Reuses an asset already downloaded, matches the enemies' uniform, and needs no extra model or animation | A separate rigged arms model with animations: better, but another asset and clip set. Reusing the aim clip's arm pose: the hands sit side by side there, wrong for a rifle |
| 23 | Untextured weapon models are coloured by region with vertex colours (painter functions of position along the barrel and height) | The files have one material and no UVs, so regions cannot be assigned any other way without editing the models | Texturing in a modelling tool: better detail, a manual step per model |
| 24 | Sixty-nine more cover pieces in five heights (0.7 m to 2.6 m) are scattered by the map seed with at least 3.2 m between pieces; 1.1 m and 2.2 m crates form climbable steps | Low pieces protect a crouching player, tall ones a standing player, and stacks give vantage points; the spacing keeps every gap walkable for the pathfinding grid | Terrain height changes: would need sloped collision and a different pathfinding grid |
| 25 | `RULES.enemyAccuracy` multiplies every enemy's hit chance; it is set to 0.6 | One dial is easier to tune than four per-type values, which stay as the relative difference between types | Lowering each type's accuracy separately |

## Tunable items (all provisional, all in `src/config.js`)
1. **Difficulty**: `RULES.enemyAccuracy` (0.6). Standing still in the open against wave 1's eight riflemen, the player now lasts about 17 seconds from the first hit (measured); it was about 10 seconds at 1.0.
2. **Pacing**: first contact in wave 1 takes about 25 seconds; 14 seconds between waves; 120 enemies across six waves.
3. **Ammo economy**: rifle reserve 180 with a cap of 300; enemies drop ammo 30% of the time; each resupply adds 180. The pistol has unlimited reserve ammo as a fallback.
4. **Feel**: recoil, spread, movement speed, and the aim-down-sights multiplier.
5. **Tone**: the menu story and radio lines (`WAVES[].radio` and `STORY` in `config.js`, plus the intro text in `index.html`).
6. **Title**: "The Last Block" is a working title.
7. **Economy**: rewards are 100 (rifleman), 120 (assault trooper), 300 (heavy gunner), and 150 (drone), plus 50 for a headshot. The sniper costs 2,000 and 10 rounds cost 400; the Desert Eagle costs 1,200 and 14 rounds cost 250; a grenade costs 300 and a medkit (50 health) costs 350. A full clear of wave 1 pays 800 and waves 1 and 2 together pay 2,280 before headshot bonuses, so the sniper is affordable during wave 2.
8. **Sniper**: 230 damage (2.5x to the head), 5-round magazine, 1.25 s between shots, 20 reserve rounds with a cap of 30.
9. **Desert Eagle**: 95 damage (2.2x to the head), 7 rounds, 0.38 s between shots, 36 reserve rounds with a cap of 60.

## Known limitations
- Desktop keyboard and mouse only; no touch controls. Chrome or Safari is recommended.
- The map boundary is an invisible wall.
- Enemies only stand; they do not take cover or throw grenades. The hit boxes stand upright while the animated body leans when running, so a head shot on a sprinting soldier can register as a body shot.
- The first-person arms hold one fixed pose per weapon: the fingers do not move and the hands do not work the magazine during a reload.
- Lit-window patterns repeat, because buildings of one style share a texture.

## Fixed issues

| Issue | Cause | Fix | Regression guard |
|---|---|---|---|
| Soldiers got stuck beside cars and the wave stalled | Only obstacles taller than 2 m were in the grid | All obstacles go into the grid, cells block conservatively, cell size reduced from 4 m to 2 m | Test 7 in `tests/core.test.mjs`: 60 player positions by 15 spawn points, walked with collision |
| Assault troopers stalled at barriers without firing | They closed in along a straight line while engaged | Closing in now follows the flow field | Same test |
| A supply crate was consumed even when everything was full | Missing cap check | Not picked up when ammo, health, and grenades are all full | None |
| A grenade thrown against a wall got stuck inside it | The release point could already be inside the wall | Released from the camera position when the path ahead is blocked | None |
| Grenades hurt targets through walls | The blast did not check occlusion | Added a ray check from the blast point to the target | None |
| After a release, players saw the old game or a mix of versions until a hard refresh | Nothing versioned the module URLs and the host caches them | See decision 14 | Test 9 in `tests/core.test.mjs` fails when `index.html` is not stamped for the current files |
| No firing or looking in browsers without mouse lock | Input assumed the lock had succeeded | See decision 9; a click buffer was also added | None |

## Verification
- `npm test`: nine tests, including the version stamp check (ray casting, low-cover occlusion, collision, map points clear of obstacles, all spawn points reachable, valid wave data, walking simulation with collision, shop data).
- Browser run of the new features: kill rewards, opening the armory, a refused purchase when short of money, buying the sniper, the second sidearm, ammo, a grenade, and a medkit (including refusals when full), a scoped shot, a sidearm shot, and pause, resume, and return to the main menu with real key presses and clicks.
- Browser run (`?nolock=1` with `window.__game.step()`): menu, combat, death screen, restart, grenades and drones, and a full six-wave clear, with no console errors.
- Firing and looking were verified with real mouse events.
- Arms, paint, cover, accuracy: each weapon was checked at the hip and aimed with the model arms; the three painted weapons were inspected from the side; with the new cover the map tests pass and a full six-wave run completed with no stuck enemies; the survival time above was measured in the browser.
- Rigged soldier: all four clips were inspected in the viewer; in game, running, aiming, a headshot kill with the death clip, body damage on a heavy, tint and scale per type, and a full six-wave run (120 kills, every soldier on the GLB model, no console errors) were checked.
- GLB weapons: each of the four was checked in the viewer and in game (hip and aimed), fired once, and the sniper scope still hides the model; the loader and every model are requested with version hashes.
